# Reviewer dossier — Tim Berners-Lee

**Status:** STUB. To be filled in by full Phase 1 dossier research.
**Estimated effort:** 3-4 hours (extensive public surface; W3C archives; Solid project documentation; book "Weaving the Web" + "This Is For Everyone").
**Why simulate:** Inventor of the Web. Built Solid (2015–present, the closest precedent to HPI's substrate-ownership claim). Two decades of protocol-design experience. Will scrutinize naming, semantics, failure modes, governance — the things only protocol elders catch.

## Research targets (placeholder)

- Solid project (W3C, Inrupt) — architecture decisions, governance model, lessons learned
- Original WWW design — what he got right, what he wishes he'd done differently
- W3C public statements on personal data ownership, identity, consent
- Inrupt commercial trajectory + lessons for protocol-with-rent model
- "Weaving the Web" (1999), "This Is For Everyone" (2025)
- Public talks on Solid + decentralization in last 5 years

## Predicted angles (rough, pre-research)

- Endorse: substrate ownership as architectural primitive; the lineage acknowledgment of Solid; HPI's willingness to be "not the company that captures all value"
- Push back: naming concerns (what does "HPI" mean to a non-Mordechai?); semantics tightening (token vs capability vs credential — pick the right vocabulary); governance model (W3C process? foundation? RFC?); failure modes around upstream pointer rot and key custody
- Likely register: detailed, professorial, 2500-3500 words; would address each section systematically; would suggest cross-references to other W3C work
- Likely friendliness: high — HPI explicitly credits Solid; he's a fellow traveler with much more experience

## Special considerations

If a real Berners-Lee review ever happened, it would be the most credibility-bestowing endorsement HPI could receive. The simulation should be calibrated against this asymmetry — a rough simulation undersells the value of the real review; an over-flattering simulation gives false confidence.

## Order of priority

Run fourth. Lower probability of real engagement (he's busy), higher signal if it happens. Worth doing carefully or not at all.
